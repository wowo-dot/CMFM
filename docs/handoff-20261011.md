## What AL gives CMFM (API 1.7)

All in `third_party/al/al_plugin.h`; AL's `docs/plugin-guide.md` explains
how they fit.

| Service | Use in CMFM |
|---|---|
| `al_plugin_info` / `al_plugin_init` | load, ordering (`order`, `load_before`), `dependencies` |
| `api->log`, `api->set_status` | `plugins\cmfm.log`; ACTIVE, DEGRADED or DISABLED with a reason |
| `api->get_interface` / `api->publish_interface` | AL's services; CMFM publishes `cmfm.<...>` tables for other plugins |
| `al.d3d12` 1.0 | SWAPCHAIN_CREATED, PRE_PRESENT (draw overlays here), POST_PRESENT, PRE_RESIZE, POST_RESIZE; status |
| `al.input` 1.0 | hotkeys, key and pad state, the game window's messages, capture for menus (keyboard, mouse, XInput pad) |
| `al.frame` 1.0 | callbacks on the game thread every frame; tasks posted to it |
| `al.hooks` 1.0 | shared chains on game functions, pattern-checked (later: the game's own menus) |
| `al.game`, `al.scanner` | game version and exe hash; cached pattern scans |
| Phases | PRE_MAIN … GAME_READY (title screen up) … EXITING, SHUTDOWN; opt-in by bitmask |

Notes from AL's side:

- Interfaces from `get_interface` stay valid until the process exits.
  `al.d3d12` subscriptions close when PRE_MAIN ends: subscribe from
  `al_plugin_init` or PRE_MAIN.
- `al.input` capture: a menu captures when it opens and releases when it
  closes. AL ends any capture when a plugin faults or is disabled, the game
  loses focus, or the game exits. Another plugin's capture suppresses your
  hotkeys. AL logs no keys or text, and neither should CMFM.
- Window messages from `al.input` arrive on the window's thread (the
  WinMain thread); frame and hotkey callbacks on the game's frame thread;
  `al.d3d12` Present events on the game's present thread (AL's plugin
  guide, "Threads"). ImGui is not thread-safe: pick one thread for its
  context and hand input over to it.
- A published name must start with the plugin's name and a dot
  (`cmfm.menu`). Plugins that start before CMFM cannot get the table in
  their `al_plugin_init` unless CMFM loads first: decide between a low
  `order` for CMFM, a `dependencies` entry in each client, or clients
  asking at a later phase.
- AL's own start-up warnings are a plain Windows message box today
  (AL `src/core/startup/runtime.cpp`). Showing them in CMFM instead is an
  AL change: put it in `docs/al-requests.md` when CMFM can show popups.

## Requirements

The DLSS mod's needs are AL `docs/requirements-dlss-mod.md`, sections 3
(graphics coordination) and 4 (settings menu). In short:

- **MUST** take a typed settings schema per plugin (enum, bool, int or
  float range, read-only status line) with get, set and validate
  callbacks; each setting `live` or `restart required`.
- **MUST** keep the plugin's own config as the source of truth
  (`mhw_dlss.ini` stays hand-editable); CMFM reads and writes through the
  plugin.
- **MUST** handle keyboard, mouse and controller, a configurable hotkey,
  and block game input while the menu is open (`al.input` capture).
- **MUST** let a plugin show a warning popup or notification (text,
  severity, "don't show again").
- **MUST** draw into the game-facing back buffer before the presentation
  owner's Present, on the game's queue, with correct barriers, so DLSS
  frame generation treats it as UI and does not smear it. Release
  back-buffer references at PRE_RESIZE, re-acquire at POST_RESIZE.
- **SHOULD** send menu open and close events.
- **SHOULD** offer a status page per plugin (mode, render size → output
  size, FG multiplier, Reflex state, last failure); **MAY** offer debug
  pages (live counters).
- **SHOULD** later grey out or annotate the game's own AA and DLSS options
  while the mod owns AA (needs the game's Options menu reversed).
- **MUST** cost close to nothing per frame with the menu closed.

The DLSS mod's settings, to register first:

| Setting | Values |
|---|---|
| frame_generation | off, 2x, 3x, 4x, 6x (3x and up need RTX 50) |
| upscaling | DLAA, Quality, Balanced, Performance, Ultra Performance |
| reflex | on, boost |
| hud_less | on/off (diagnostic) |
| status overlay | on/off |

## Suggested order

1. **Overlay** (the riskiest part first): Dear ImGui with its D3D12
   backend, drawn in `al.d3d12` PRE_PRESENT into the current back buffer
   on the game's queue; a test window toggled by an `al.input` hotkey with
   capture; resize and full-screen toggles; measure the closed-menu cost.
   Test with the DLSS mod's frame generation on and off: the menu must not
   smear in generated frames.
2. **The interface draft** `include/cmfm/cmfm.h` (`cmfm.menu` 1.0): the
   settings schema, status pages, popups, open and close events. Pure
   unit tests, and a small example client plugin.
3. **Pages:** settings and status pages from registered plugins; popups;
   CMFM's own settings (hotkey, scale) in its AL data folder.
4. **DLSS mod integration:** a handoff to the DLSS session with the
   interface and the five settings above.
5. **Look:** a theme close to MHW. Later, research entries inside the
   game's own menus (decisions.md item 2).
